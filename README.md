
# Trendwatcher: Трендвотчер по финтех-публикациям

Прототип сервиса, который находит важные открытые публикации про финтех и банковские продукты, отличает полезные сигналы от шума и превращает их в понятный дайджест для внутренних команд банка.

### 1. Установка зависимостей

Через Poetry (рекомендуется):
```bash
poetry install
```

Через pip:
```bash
pip install -r requirements.txt
```

### 2. Запуск базы данных

```bash
docker compose up -d pg adminer
```

Зайдите на http://localhost:8081 и выполните SQL-запрос для включения расширения векторного поиска:
```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

### 3. Применение миграций

В терминале проекта выполните:
```bash
alembic upgrade head
```

### 4. Запуск пайплайна обработки данных

```bash
# Добавить источники в БД
python seed_sources.py

# Парсинг публикаций (сбор и первичная очистка)
python -m backend.services.scraper

# Векторизация и кластеризация (поиск дублей и смысловых групп)
python -m backend.services.embedder

# Генерация карточек сигналов (оценка и структурирование)
python -m backend.services.signal_generator
```

### 5. Запуск веб-интерфейса

```bash
uvicorn backend.api.main:app --reload --host 0.0.0.0 --port 8000
```

Откройте в браузере: http://localhost:8000

##  Логика работы прототипа

Проект реализует ключевой сценарий: **Входные материалы → Фильтрация шума → Оценка важности → Краткая выжимка → Понятный вывод**.

### 1. Сбор и фильтрация шума (`scraper.py`)
- Асинхронный парсинг открытых источников (VC.ru, TAdviser и др.).
- Использование библиотеки `trafilatura` для извлечения только основного текста статьи (автоматическое удаление рекламы, меню, футеров).
- Первичный отсев нерелевантного контента по ключевым словам (СБП, цифровой рубль, биометрия, финтех и т.д.).

### 2. Борьба с дублями и кластеризация (`embedder.py`)
- Векторизация текста с помощью легковесной модели `cointegrated/rubert-tiny2` (поддержка русского языка).
- Сохранение эмбеддингов в PostgreSQL через расширение `pgvector`.
- Расчет косинусного сходства между публикациями. При схожести > 85% материалы объединяются в один кластер.
- **Выделение первоисточника:** внутри кластера одна публикация помечается как `is_primary`, что позволяет отличать оригинал от пересказа.

### 3. Оценка важности и генерация сигнала (`signal_generator.py`)
Формирование структурированной карточки сигнала по заданному формату:
- **Headline:** Короткий заголовок.
- **Hotness:** Оценка значимости сигнала (1-10).
- **Why now:** Объяснение актуальности события прямо сейчас.
- **Category:** Автоматическая категоризация (BANKING_PRODUCT, PAYMENT_SERVICE, REGULATION, MARKET и др.).
- **Summary:** Краткая выжимка сути.
- **Draft:** Готовый черновик поста/заметки для внутренней команды.
- **Sources:** 1-3 проверяемые ссылки на исходные публикации (обеспечивает прозрачность и доверие).

##  Ограничения прототипа

В соответствии с требованиями к прототипу, данное решение:
1. Не является production-ready системой промышленного мониторинга в реальном времени.
2. Фокусируется на банковских продуктах, финтех-сервисах и пользовательских сценариях, а не на оценке влияния на рынки, активы и котировки.
3. Генерация полей сигнала (`why_now`, `draft`) на данном этапе реализована через эвристические правила. Архитектура позволяет легко заменить этот модуль на вызов API LLM (YandexGPT, GigaChat или локальный Ollama) без изменения остального кода.
